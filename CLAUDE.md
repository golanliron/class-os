# ClassOS — Product Context

We are building a pedagogical operating system for teachers.
Hebrew name: מערכת ההפעלה של שנת ההוראה

This is NOT a lesson plan generator.
This is NOT an AI chat for teachers.
This is a full year teaching management system.

The system converts Ministry of Education curriculum into a live yearly teaching plan based on:
1. School calendar (holidays, events)
2. Teacher schedule (days, hours, classes)
3. Class level and student list
4. Actual teaching progress and feedback

First product: History, Grade 7, State education (ממלכתי).

## Core Principle

The teacher should NEVER start from a blank page.
She opens the system and sees: her next lesson, her materials, her progress.

## Technical Stack

- **Framework:** Next.js 15 + TypeScript
- **Styling:** Tailwind CSS
- **Database:** Supabase (PostgreSQL + Auth + RLS + Edge Functions)
- **Deployment:** Vercel
- **Font:** Heebo (Hebrew optimized)
- **Direction:** RTL throughout
- **Language:** Hebrew UI, English code

## Development Rules

1. **Do not overbuild.** Build the minimum needed, then iterate.
2. **Infrastructure first.** Auth, DB, roles, schedules — before any fancy features.
3. **No AI in MVP.** Keep AI features completely separated from core planning logic. The yearly plan is generated by algorithm, not AI.
4. **Curriculum is sacred.** The system does NOT invent curriculum. Every lesson connects to a curriculum topic from the database.
5. **Progress drives everything.** Every delivered lesson updates class progress. The next lesson depends on what happened in the previous one.
6. **Support, not surveillance.** Principal dashboard helps teachers, doesn't police them. Language should be supportive.
7. **School language only.** Use כיתה, שיעור, נושא, יחידה — not מודול, יוניט, אובייקט, אנטיטי.
8. **Mobile responsive.** Teachers will use phones. Design for mobile first.
9. **One click to next lesson.** From login to the next lesson = maximum 1 click.
10. **Clean and calm UI.** White space, soft colors, no visual clutter.

## Four Engines

The product has four core engines:

1. **Year Engine** — Converts syllabus + schedule + calendar into a yearly plan with dated lessons
2. **Next Lesson Engine** — Determines the correct next lesson based on actual progress
3. **Adaptation Engine** — (Phase 2) Adjusts lessons to class level and needs
4. **Pedagogical Management Engine** — Gives principals and coordinators actionable insights

## MVP Scope (Phase 1)

Build:
- Auth + roles (teacher, principal)
- Schools + classes + students
- Teacher schedule
- History Grade 7 curriculum (seed data)
- Year Engine (automatic yearly plan)
- Weekly view + lesson view
- Post-lesson reporting
- Basic Next Lesson logic
- Basic principal dashboard

Do NOT build:
- AI features
- Worksheet generator
- Presentation generator
- Student adaptations
- Coordinator features
- Content admin panel
- Additional subjects
- Mobile app

## File Structure Convention

```
src/
  app/                    # Next.js app router
    (auth)/              # Login, signup
    (teacher)/           # Teacher pages
      dashboard/
      week/
      lesson/[id]/
      plan/
      class/[id]/
    (principal)/         # Principal pages
      dashboard/
      teacher/[id]/
      class/[id]/
  components/
    ui/                  # Shared UI components
    teacher/             # Teacher-specific components
    principal/           # Principal-specific components
  lib/
    supabase/           # Supabase client, types
    engines/            # Year engine, next lesson engine
    utils/              # Helpers
  types/                # TypeScript types
```

## Naming Conventions

- Database: snake_case (planned_lessons, curriculum_topics)
- TypeScript: camelCase for variables, PascalCase for types/components
- Files: kebab-case (yearly-plan.tsx, next-lesson-engine.ts)
- Commits: Hebrew description of what was done
